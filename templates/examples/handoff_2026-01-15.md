# Handoff 2026-01-15 — checkout-flow refactor

## What was done
- Extracted the Stripe call out of `CheckoutForm` into `lib/payments/charge.ts`
  (a thin wrapper so the third-party SDK is mockable per testing rules). 11 tests.
- Found + fixed the double-charge bug: the form's submit handler wasn't disabled
  during the in-flight request. Fix is a `useRef` guard, not state (state lagged a
  render). Regression test added: `charge.test.ts` → "ignores re-entrant submit".

## What needs doing next
- The refund path still calls Stripe directly in `RefundButton` — same extraction
  pending. Lower priority; no bug there, just consistency.
- `npm run validate` passes, but the e2e suite is skipped in CI (no Stripe test
  key in the runner). Decide: wire a test key, or mock at the network boundary.

## Key context
- We deliberately did NOT add a retry on charge failure — the PM wants the user to
  see the error and re-submit, not silent retries that could double-charge. If you
  see "should we retry here?", the answer is no; it's a product decision, not an
  oversight.
